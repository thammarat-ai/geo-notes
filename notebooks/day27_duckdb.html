Day 27 · New tool — DuckDB + spatial: ยกงานเชิงพื้นที่ลง SQL แล้วเทียบคำตอบ

#30DayMapChallenge 2026 · 27 พ.ย. 2569 · โจทย์: “The challenge has always been about learning things. Try out a new tool in your mapmaking workflow.”

เครื่องมือใหม่ของซีรีส์นี้คือ DuckDB + duckdb-spatial (v1.5.5, ส่วนเสริม eb1e57c, มีฟังก์ชัน ST_* 158 ชื่อ) — ยกงานที่ 26 วันก่อนหน้าทำด้วย geopandas/shapely/pyproj ไปทำใน SQL ล้วน ๆ แล้วถามว่า คำตอบเหมือนกันไหม ตรงไหนต่างกัน และต่างกันเพราะอะไร

งาน คำถามที่เคยตอบไปแล้ว SQL ที่ใช้
A จังหวัดของ 83 จุด (Day 8/22/23/26) ST_Contains join กับ NE admin_1 4,596 polygon ที่อ่านด้วย ST_Read
B จุดไหนอยู่ในเขตพื้นที่คุ้มครอง (Day 21) ST_Contains join กับ 163 ห่วงใน data/day27_rings.json.gz
C ระยะจากจุดไปโหนดลำน้ำใกล้สุด (Day 26) ST_Distance_Spheroid บนตารางโหนด 56,946 แถว
D พื้นที่ประเทศไทย/จังหวัด (Day 22) ST_Area_Spheroid

กับดักสองตัวที่เจอจริง (วัดจำนวนไว้ทุกตัว)

  1. ตระกูล *_Spheroid และ ST_Distance_Sphere รับพิกัดเป็น (ละติจูด, ลองจิจูด) ซึ่งกลับด้านกับ ST_Point / ST_Contains / ST_Area (planar) และกับมาตรฐาน GeoJSON/WKT ผลคือถ้าป้อนตามมาตรฐานจะได้ NaN เงียบ ๆ ไม่ขึ้น error — ทดสอบ 4 เคสระยะ ได้ NaN 4/4, 40 ห่วง ได้ NaN 40/40, พื้นที่ไทย 1 polygon ได้ NaN · เมื่อป้อนกลับด้านได้ค่าที่ ตรงกับ pyproj ต่างสูงสุด 0.000 ม. และ 0.0000 ตร.กม.
  2. ST_Transform ใน build นี้คืน inf ทุก EPSG ที่ต้องแปลงจริง (3857 / 32647 / 32648 / 6857) และไม่รับ proj4 string → projection Equidistant Conic ที่ซีรีส์ใช้อยู่ ทำใน SQL ไม่ได้ งานนี้จึงวัดระยะแบบ spheroid แทนระยะระนาบ ซึ่งกลายเป็นข้อเปรียบเทียบที่ดี (ดูตอน C)

ผลเทียบ (เต็มใน day27_agree.csv)

  • A: SQL กับ geopandas ให้จังหวัดตรงกัน 83/83 (รวม 3 จุดที่ทั้งสองไม่พบ polygon)
  • B: SQL กับ shapely ให้คู่ (จุด, ห่วง) ตรงกัน 40 = 40 — แต่ได้ 24 จุด เทียบกับ 25 จุด ที่ Day 21 รายงาน เพราะห่วงชุดนี้คือเวอร์ชัน ลดรายละเอียด ที่ Day 21 เก็บไว้วาด (มัธยฐาน 8 จุด/ห่วง) → ต่างกันเพราะ การเตรียมข้อมูล ไม่ใช่เพราะเครื่องมือ
  • C: SQL กับ pyproj ต่างสูงสุด 0.000 ม. (rho 1.000000) · ตรวจข้ามวันกับ Day 26 ต่างสูงสุด 0.048 ม. · แต่ คนละนิยาม: ระยะระนาบ EQ ต่างจาก geodesic มัธยฐาน 0.643 ม. (0.1399%) สูงสุด 26.757 ม.
  • D: SQL 514,453.7 = pyproj 514,453.7 ตร.กม. (ต่าง 0.00) · ค่า EQ ที่ซีรีส์ใช้ 512,593.1 ตร.กม. ต่ำกว่า geodesic −0.3617% ซึ่งทำซ้ำตัวเลขของ Day 22 ได้ตรง

def gj_coords(js):
    """ดึงพิกัดเส้นนอกสุดจาก GeoJSON ที่ SQL ส่องออกมา (ST_AsGeoJSON) → Nx2 array"""
    try:
        g = json.loads(js)
    except Exception:
        return None
    if g.get("type") == "Polygon":
        ring = g["coordinates"][0]
    elif g.get("type") == "MultiPolygon":
        ring = max(g["coordinates"], key=lambda c: len(c[0]))[0]
    elif g.get("type") == "LineString":
        ring = g["coordinates"]
    else:
        return None
    a = np.array(ring, dtype=float)
    return a[:, :2] if a.size else None

def _clean(o):
    if isinstance(o, dict):
        return {k: _clean(v) for k, v in o.items()}
    if isinstance(o, (list, tuple)):
        return [_clean(v) for v in o]
    if isinstance(o, (np.bool_, bool)):
        return bool(o)
    if isinstance(o, (np.integer, int)):
        return int(o)
    if isinstance(o, (np.floating, float)):
        return None if not math.isfinite(o) else float(o)
    if isinstance(o, np.ndarray):
        return _clean(list(o))
    return o
